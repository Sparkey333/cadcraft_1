# Open-source and low-cost CAD alternatives: what users say (2024-2026)

Research worker: `research:opensource-reviews`. Date: 2026-10-21.
Scope: FreeCAD 1.0/1.1 (and its civil/geomatics/BIM workbenches), LibreCAD 2.2, QCAD (Community vs Professional), BRL-CAD, nanoCAD Free, CADCraft / ArtCraft crafting apps, plus what site designers and surveyors do with QGIS, Blender-GIS and spreadsheets instead of CAD.

## 0. Method and limits (read first)

- **What was reachable.** Web search worked for the first ~16 queries, then the shared per-turn search budget was exhausted. Direct fetches succeeded only for `github.com` (HTML pages, not the API) and `sourceforge.net`. Every other review host failed DNS through the proxy: Capterra, G2, AlternativeTo, TrustRadius, Software Advice, GetApp, SaaSworthy, Slashdot, Wikipedia, blog/wiki/forum.freecad.org, qcad.org and forum.qcad.org, community.osarch.org, nanocad.com, getartcraft.com, the third-party ArtCraft guide sites, Medium, Neowin, TechSpot, Hacker News, and Reddit (blocked outright).
- **Consequence.** Capterra, G2, AlternativeTo and QCAD-forum figures below come from **search-result snippets only** and are marked `[snippet]`. SourceForge and GitHub figures were read from the live pages on 2026-10-21 and are marked `[fetched]`. Anything I could not confirm is marked `unverified`.
- **No GPL source was read.** Only GitHub issue/PR *descriptions and discussion text*, READMEs and release notes of FreeCAD, LibreCAD, QCAD, BRL-CAD, freecad.trails and BlenderGIS were read; no code.
- **Dates on GitHub listings.** The GitHub HTML pages show relative dates; the summariser rendered them as absolute 2026 dates. Issue numbers are reliable; treat day-level dates as approximate.
- **Reddit / Hacker News / Discord.** No Reddit or HN thread could be opened. Searches aimed at Reddit returned no Reddit results. This is a gap: practitioner "would I switch" threads are under-represented, and the "wishes" section is synthesised mostly from issue trackers and SourceForge/Capterra themes.

## 2. FreeCAD 1.0 / 1.1 (and 26.3)

### Release facts
- FreeCAD 1.0.0 was published on GitHub on 19 November (2024); the post lists four headline changes: topological-naming (TNP) mitigation code, an integrated Assembly workbench, a materials system and many UI/UX improvements. 501 people reacted (288 thumbs-up, 246 party, 153 hearts). [fetched] https://github.com/FreeCAD/FreeCAD/releases/tag/1.0.0
- FreeCAD 1.1.0 was published on 25 March (2026) by adrianinsaval, "massive quality-of-life improvements and new features across all workbenches"; 284 reactions (138 thumbs-up, 135 party, 118 hearts). [fetched] https://github.com/FreeCAD/FreeCAD/releases/tag/1.1.0 . The project blog dates it 24-25 March 2026 [snippet] https://blog.freecad.org/2026/03/25/freecad-version-1-1-released/ . Coverage cites transparent Part Design previews, interactive draggers for Fillet/Chamfer, three-point lighting, Clarify Selection, FEM animation, rebuilt CAM tool library, Wayland fixes [snippet] https://alternativeto.net/news/2026/3/freecad-1-1-adds-three-point-lighting-part-design-previews-and-major-fem-upgrades
- The project has moved to calendar versioning: the GitHub Discussions page carries the announcement "FreeCAD 26.3: release branch on September 30" (18 votes) and threads about "26.3rc2"; Wikipedia (snippet) says 26.3 was "formerly known as 1.2". [fetched] https://github.com/FreeCAD/FreeCAD/discussions
- The 1.1 ICON Polls review gives it 3.0/5 and calls it "not a flashy overhaul"; a commenter on the release blog called 1.1 "minor tweaks" after the big 1.0. [snippet]

### Praise
- Free and open, "comparable to the other major CAD packages" for someone who invests the time (SourceForge directory review, woodworking instructor, 2022) [fetched].
- Long-time users say they have had no particular crash problems since 0.14 and that newer versions have file recovery; many crashes are attributed to modelling practice and operation order (Bambu Lab forum, 2024-25) [snippet] https://forum.bambulab.com/t/first-time-user-best-cad-software-is/90374?page=3
- 1.0 fixed the two things everyone complained about for a decade (TNP, assembly) and got broad press coverage [snippet] https://alternativeto.net/news/2024/11/freecad-1-0-launches-with-enhanced-ui-ux-built-in-assembly-workbench-and-tnp-fixes/
- G2 reviewers score import/export highly (8.3 / 8.4) [snippet].
- Active, constructive community: Discussions page shows the 26.3 release cycle, a 138-comment BIM roadmap thread, a nesting-for-CAM design thread, a Steam-release proposal (27 comments) [fetched].

### Complaints
1. **Crashes and instability (severity: high).** GitHub shows **362 issues with "crash" in the title created since 2025-01-01** (as of 2026-10-21); the 15 newest (Oct 2026) hit TechDraw (double free, deleting a page with dimensions), Sketcher (context menu on quitting a sketch), STEP export (stack smashing), stylesheets, gimbal transform, impossible fillets on 26.3rc2, negative-taper pad, Assembly gear joint, Spreadsheet on macOS, and several packaging crashes (bundled NumPy SIGILL on older CPUs, font cache, AppImage). [fetched] https://github.com/FreeCAD/FreeCAD/issues?q=is%3Aissue%20crash%20in%3Atitle%20created%3A%3E%3D2025-01-01 . Note there is no "Crash" label (that filter returns 0), so counts depend on titles. Capterra's summary theme is "frequent bugs and instability" [snippet]. Older SourceForge reviews (2013-2015) report segmentation faults with Python scripting and unreliable OpenCASCADE booleans [fetched] https://sourceforge.net/projects/free-cad/reviews/?offset=25
2. **Topological naming is mitigated, not solved (high).** Issue #29154 (April 2026, 1.1 dev build): shortening a pad by 5 mm flipped a sketch dimension, pockets lost their faces, chamfers/fillets lost edges. A member states TNP "can be mitigated but not fully fixed"; a V2 algorithm (PR #31040) is in progress and the issue is still open in the "Toponaming Integration" project. [fetched] https://github.com/FreeCAD/FreeCAD/issues/29154 . Of 19 "topological naming" issues opened since 2025, 8 are still open (e.g. #27266 chamfer loses face after Thickness; #22482 TechDraw dimensions corrupted after wall sketch change). [fetched] https://github.com/FreeCAD/FreeCAD/issues?q=is%3Aissue%20%22topological%20naming%22%20created%3A%3E%3D2025-01-01
3. **Not a 2D drafting / DWG replacement (high for this audience).** AlternativeTo commenters: FreeCAD "has no drafting functionality worth speaking of" and is "certainly not an AutoCAD replacement" [snippet] https://www.alternativeto.net/software/autocad/ . 122 DXF-tagged issues since 2025; open ones include silent failure of automatic DWG export (#31835), DXF import leaving the app stuck with a busy cursor (#31637), single points not exported (#30675), text scaled by the wrong multiplier on the C++ importer (#30043), mirrored blocks (#28905, closed). [fetched] https://github.com/FreeCAD/FreeCAD/issues?q=is%3Aissue%20dxf%20created%3A%3E%3D2025-01-01 . A 2015 reviewer could not produce a dimensioned workshop drawing and found "2D CAD much more intuitive" [fetched].
4. **Learning curve and UI complexity (medium).** G2 ease-of-use 7.6-7.8/10 [snippet]; SourceForge reviews: "complex interface", undocumented sketch-attachment rules, "frustrating compared with Inventor and Creo" [fetched]; a 2026 Discussions thread says panel controls are "confusing, and have state-dependent behavior" [fetched].
5. **Performance regressions (medium).** Discussions: "PartDesign: Polar is stalling everything" (April 2026, also issue #29536), "FCstd zip slow" [fetched].
6. **Support (low-medium).** A Capterra switcher from AutoCAD cites "near no customer service and sometimes sub-par tutorials" [snippet] https://www.capterra.com/p/167527/FreeCAD/reviews/?page=2
7. **Civil / geomatics workbenches are small external add-ons (high for site work).** The Trails workbench README lists survey-data import, point groups, surfaces, regions/cross-sections, volume areas and tables, building pads and LandXML alignment import, but warns packaged releases lag the dev branch, requires submodules, has little usage documentation, 83 stars and 22 open issues [fetched] https://github.com/joelgraff/freecad.trails . A conference abstract says GIS integration "is in its nascent stages" and effort went to "stability and prototyping" [snippet] https://av.tib.eu/media/57250 . A separate "Road" workbench fork by HakanSeven12 was discussed on OSArch in Feb 2025 and explicitly has no GIS tools [snippet] https://community.osarch.org/discussion/2782/freecad-road-workbench ; the GitHub URL I tried for it returned 404 (unverified location).
8. **BIM.** The BIM roadmap discussion is the most-commented thread (138 comments), and a 2026 issue reports the default structure extrusion direction can flip (#26532, closed) [fetched]. No 2025-26 architect review of BIM-on-FreeCAD could be opened (Medium unreachable) - gap.

## 3. LibreCAD 2.2

### Release facts
- Latest stable is **2.2.1.6** (17 Oct, 2026 per asset timestamps); point releases 2.2.1.1-2.2.1.5 through the year; a 2.2.2-alpha line lives on master; no 2.2.2 or 3.0 stable has shipped. 2.2.1.6 fixes crashes in Undo/Redo, property dialogs, clipboard and block handling, hatches and recursive snapping inside filled hatches; fixes unsafe binary DXF/DWG value reads; handles DWG text direction; adds bounded hyperbolas, RTL MText, CJK fonts. 2.2.1.5 added a crash handler. [fetched] https://github.com/LibreCAD/LibreCAD/releases
- Open issues: **567** on 2026-10-21 [fetched] https://github.com/LibreCAD/LibreCAD/issues

### Praise
- "Lightweight and practical", reads DWG, used for floor plans and sections (Portuguese review 2023-10), 2D woodworking layouts and construction drawings with DWG shared between PCs (retiree, 2023-03), "excellent program that works well" (2024-01), thanks to devs (2026-03) [fetched] https://sourceforge.net/projects/librecad/reviews/
- Capterra value-for-money 4.2/5 is its best sub-score; "drafting features comparable to paid programs at no cost" [snippet].
- Bugs get fixed quickly (2014 review) and the 2025-26 crash issues are overwhelmingly **closed** (20 of 25 shown) [fetched].
- Maintainers respond within a day on GitHub, e.g. command aliases now editable in an .alias file with a UI planned (#3162, Oct 2026) [fetched].

### Complaints
1. **DWG support is incomplete and the project does not promise it (high).** Issue #3064 (Oct 2026, "Significantly improve DWG import compatibility"): the reporter says LibreCAD "often fails to open DWG files, sometimes opens them empty or with missing entities", and - notably - compares it with **CADCraft, which "has many bugs but opens more DWG files"**. Contributor sand1024 replied that DWG is proprietary and suggested converting to DXF with an online converter; member dxli said DWG support "was still being implemented for 2.2.2-alpha and LibreCAD_3". Closed as completed without a linked fix. [fetched] https://github.com/LibreCAD/LibreCAD/issues/3064 . Of 20 "dwg" issues since 2025, 4 remain open (#2263 "Unable to open *.dwg file", Aug 2025) [fetched]. Comparison tables list DWG as "import only"; competitor blogs (ZWSoft, CADblock) stress this, with obvious bias [snippet]. Positive counterpoint: several SourceForge reviewers say DWG reading works for them [fetched].
2. **Reader fragility (medium).** PR #2855 (merged 2026-09-14): after an earlier reader change, master's DXF reader opened only **28 of 1,483** test DXF files (including LibreCAD 2.2's own saves and all 1,265 bundled library parts); the fix brought it to 1,482. Only master/2.2.2-alpha was affected, but it shows how easily a strict reader regresses. [fetched] https://github.com/LibreCAD/LibreCAD/pull/2855 . Issue #2781 (Aug 2026): old DWG/DXF from DraftSight "open distorted" - fixed in October [fetched] https://github.com/LibreCAD/LibreCAD/issues/2781
3. **Crashes (medium).** 37 issues with "crash" in the title since 2025-01-01; recent ones: crash changing paper size (#3017), moving a hatch (#3008), after copy/paste between files (#2921), on save in 2.2.2 alpha (#2918), undo/redo of a line (#2631), closing block edit (#2621), macOS Tahoe (#2549), inserting a block on macOS (#2452, open), drawing hatch boundaries (#2408, open). Most are closed within weeks. [fetched] https://github.com/LibreCAD/LibreCAD/issues?q=is%3Aissue%20crash%20in%3Atitle%20created%3A%3E%3D2025-01-01 . Capterra: "the application sometimes gets unresponsive" [snippet].
4. **Documentation and help (medium).** The featured lowest SourceForge review (2015): no integrated help, online manual "hard to find, incomplete, inaccurate"; repeated in 2014 and 2016 reviews; Capterra support 3.1/5; "the user manual is not available" [fetched, snippet].
5. **Printing (medium).** Print preview correct but nothing reaches the printer on US Letter (2015); "printing setup is a pain while configuring" (Capterra) [fetched, snippet].
6. **Missing capabilities (medium for site work).** No 3D; no external references; no viewports comparable to AutoCAD paper space workflows; feature requests in Oct 2026 include PDF-as-image import (#3103), three-point ellipse, focus shortcuts, reducing backup-file clutter (#3038) [fetched].
7. **Not trying to be AutoCAD (low, but relevant).** On #3162 ("emulate Auto CAD"), sand1024: "cloning AutoCAD has never been the project's goal"; AutoCAD-style right-click selection "isn't practical" [fetched] https://github.com/LibreCAD/LibreCAD/issues/3162 . Users who want AutoCAD muscle memory therefore look elsewhere.

## 4. QCAD (Community Edition vs Professional)

Primary site unreachable; all items are [snippet] from QCAD's own forum and G2.
- **Editions.** Pro = Community Edition plus plugins for DWG support, polylines, viewports and more; Pro adds scripting and advanced editing; price roughly **$50 one-time** (no subscription) with **one year of updates**, extendable at a discount; after the year Pro keeps working but cannot update. Trial of Pro is session-limited. https://forum.qcad.org/t/community-edition-vs-pro-edition/79 , https://forum.qcad.org/t/pro-edition-and-new-community-edition-features/9717
- **Performance.** Developer: Pro and CE "use exactly the same technology to render the drawing and the performance is identical"; Pro may start slightly slower because it loads more plugins. https://forum.qcad.org/t/professional-edition-slower-than-community/304
- **Praise.** G2 (13 reviews) 4.4/5; "simplicity and ease of use", product-direction 9.0/10; SourceForge directory reviewer (2021): simple, intuitive, light on resources, edits DWG/DXF without AutoCAD cost. https://www.g2.com/products/qcad/reviews , https://sourceforge.net/software/product/QCAD/
- **Complaints.** CE lacks DWG, polylines and viewports (medium); Pro users cannot pick up new CE features without renewing once C++ core changes (low); "not meant to compete with AutoCAD" (the 2021 reviewer's own con); learning curve is the most-cited G2 con (low); support 7.7/10 (one-person company). A "QCAD New User Observations" thread exists on the forum (https://www.qcad.org/rsforum/viewtopic.php?t=11378) but could not be opened - unverified content.
- **Licence note.** QCAD 3 core is GPLv3 (GitHub README) [fetched] https://github.com/qcad/qcad ; Pro plugins are proprietary. Relevance for a new app: QCAD is the clearest example of the "GPL core + paid plugins, one-time fee" model surviving for 15+ years.

## 5. BRL-CAD

- SourceForge 4.4/5 from 49 reviews, but polarised (41 five-star, 6 one-star); newest review 2022-04-28 [fetched] https://sourceforge.net/projects/brlcad/reviews/ . G2 4.5 from 1 review [snippet]. Stable release 7.42.0 (Aug 2025) per Wikipedia [snippet]. GitHub issues page returned 404 (tracker likely elsewhere).
- **Praise.** "Among the best open-source CAD tools", "superb documentation", reliable and fast for precise coordinate-based solid modelling, database-connected models, free licence [fetched].
- **Complaints (all high for 2D/civil use).** Command-line-heavy, "clunky" interface; "hard to make simple changes"; no easy fillets; doubtful IGES/STEP results (CATIA-trained design engineer, featured lowest review); install requires compiling, "for Linux experts" (2022); "almost impossible to use" without expert help; a 2012 reviewer recommends Blender for organic shapes [fetched] https://sourceforge.net/projects/brlcad/reviews/?page=2 . FitGap: steep learning curve, aimed at engineers who script [snippet] https://us.fitgap.com/products/008632/brl-cad . The Army's own modernisation article acknowledges the UI/usability revamp [snippet] https://www.army.mil/article/249241/armys_powerful_open_source_solid_modeling_system_undergoes_modernization
- **Lesson.** BRL-CAD is the cautionary tale: decades of robust geometry with almost no uptake for drafting because of installation friction and UI. Robustness alone does not win drafters.

## 6. nanoCAD Free (low-cost, not open source)

## 7. CADCraft / ArtCraft crafting apps

### Where it is discussed
- GitHub only, in practice. The repo shows ~6.3k stars, ~2.8k forks, 57 watchers, 392 open issues, 590 commits on main, dual MIT/Apache-2.0, status badge "early development", Discord at discord.gg/artcraft; Discussions are disabled; no release entries on the Releases tab (downloads point to "latest release" with a `<ver>` placeholder). [fetched 2026-10-21] https://github.com/storytold/cadcraft , https://github.com/storytold/cadcraft/blob/main/README.md
- README caveats (own words, paraphrased): SHX fonts not read yet (own stroke font substituted); entities not yet modelled are dropped on save; DXF reads R12-2018, DWG reads R13-2018 via acadrust; writes R2000 per README (a contributor on #540 says 2000-2018 is now written); a Windows note that wgpu's OpenGL path can crash some AMD driver setups before the window appears; logs written to file for crash reports. The README makes no "never crash" claim publicly. [fetched]
- Third-party pages exist but could not be opened: a guide at pasqualepillitteri.it ("CADCraft guide, the free AutoCAD alternative written in Rust"), a test write-up at jacar.es ("ArtCraft Crafting Apps: what works today, tested"), aggregator pages at craftingapps.org, artcraftweb.net, getcraftapps.com, getartcraft.app, trendshift.io (trending stats), gitdiscover.org, gitnova.dev. Snippets: one calls CADCraft "pre-alpha, so save drawings often"; the aggregators label CADCraft "in development" and the suite as 13 Rust apps with a SHA-256-verified launcher; several state they are not affiliated. [snippet] https://pasqualepillitteri.it/en/news/22966/cadcraft-free-autocad-alternative-rust , https://jacar.es/en/artcraft-crafting-apps-open-source-rust/ , https://craftingapps.org/artcraft
- **No Hacker News or Reddit thread about CADCraft/ArtCraft could be found or opened** (search budget exhausted before a site:news.ycombinator.com query ran; HN and Reddit unreachable). Unverified whether any exists.
- Notable external mention: a LibreCAD issue reporter (Oct 2026) says CADCraft "has many bugs but opens more DWG files" than LibreCAD [fetched] https://github.com/LibreCAD/LibreCAD/issues/3064

### How users report
- Many bug reports arrive through Discord and are relayed to GitHub by a "ticket-craft" bot; the reporter often has no GitHub account, so maintainer replies may never reach them (#752, #1636, #1824, #738). Maintainer replies are sometimes labelled as written by Claude Code on the contributor's behalf (#752, #738). [fetched]

### Praise (from issues)
- Fast turnaround: a Discord freeze report on big DWGs (#738, Oct 12) was answered the next day with v0.6.2 fixing hatch memory blow-up and single-core rendering; benchmarks on four 5-16 MB permit drawings went from v0.5.0 hitting an 8 GB ceiling to <1.5 s and 84-600 MB; the reporter confirmed the freeze was fixed but said it "still feels less smooth than AutoCAD on ~20 MB files". [fetched] https://github.com/storytold/cadcraft/issues/738
- Community members run real-file corpora and offer private DWG sets (#1041: 23 office DWGs; #1592: 15 BricsCAD DWGs offered) [fetched].
- Users engage deeply on parametric constraints (#1134, 12 comments) and input-model design (#1001, 9 comments), proposing concrete behaviour and sending PRs (#1555) [fetched].
- Opens more DWGs than LibreCAD (external user, above).

### Complaints (from issues)
1. **Performance and memory on real DWGs (high).** #1076: a 47.8 MB AutoCAD-2018 DWG with 985,250 entities takes ~19.6 s headless / 22-28 s to appear in the desktop app on an M1 Pro, peaking at ~4.5-5.1 GB; the intermediate DXF text (~276 MB, 5.8x the input) is built fully in memory; targets set at <12 s and <=2.5 GB [fetched] https://github.com/storytold/cadcraft/issues/1076 . #1625 (0.8.0, Windows 11): a 76.8 MB xref (710,922 objects, a PDF-import survey) attached to a 39.9 MB plan freezes the window 34 of the first 90 s, peaks at 8.4 GB; without the xref the plan opens in <1 s at 127 MB; no human reply [fetched] https://github.com/storytold/cadcraft/issues/1625 . #752 (AutoCAD 2024 user, 3rd-gen Intel): "even mouse movement is choppy", whole PC freezes on complex drawings; asks for AUDIT/RECOVER [fetched] https://github.com/storytold/cadcraft/issues/752 . #1825 mouse lag in the drawing area (Oct 21). #754 Mac frozen on a large file.

## 8. What site designers and surveyors do instead of CAD (QGIS, Blender-GIS, spreadsheets)

Evidence here is thinner than I wanted (Reddit r/Surveying and r/civil3d unreachable); the following is what was reachable.
- **QGIS is a complement, not a replacement.** A vendor-adjacent guide calls it "an open-source GIS platform rather than a CAD application" used *alongside* CAD for catchment analysis and mapping; cost is the main draw for small firms and public agencies; it "lacks full civil CAD design tools" so teams keep Civil 3D for grading, corridors and drafting [snippet] https://equatorstudios.com/the-next-generation-of-gis-tools-create-professional-maps-in-minutes/ (vendor bias: Equator sells a web GIS).
- **Surveyors favour Carlson for day-to-day boundary/topo work** because it is faster than Civil 3D, but engineers downstream use Civil 3D so the survey base must flow into it [snippet] https://www.lfinditech.com/blog/best-cad-software-for-land-surveyors (unverified detail; page unreachable).
- **Blender-GIS** (~9.5k stars) imports shapefiles, GeoTIFF DEMs, OSM XML, pulls web basemaps and OSM buildings/roads and SRTM elevation, georeferences the scene, builds terrain by Delaunay triangulation and runs terrain analysis with shader nodes; requires Blender 2.83+; OpenTopography needs a free API key since 2022 [fetched] https://github.com/domlysz/BlenderGIS . Its star count (5x LibreCAD-class projects) is the strongest quantitative signal that terrain-and-context modelling has migrated to Blender for visualisation, not to CAD.
- **Spreadsheets.** No source could be opened that documents spreadsheet-based COGO or earthwork practice in 2025-26; this is an unfilled gap (suggest a follow-up: r/Surveying "excel" "cogo", "inverse" threads; Carlson/Civil 3D forums on "import points from CSV").
- **FreeCAD Trails/Road** is the only open-source route to TIN surfaces, alignments, sections and LandXML inside a CAD, and it is a one-developer add-on with lagging releases (Section 2, item 7).

## 9. Cross-product themes (ranked by how often they decide "can I switch?")

1. **DWG fidelity, both directions.** Every product's worst thread is DWG: LibreCAD (import-only, "still being implemented"), QCAD (DWG is Pro-only), FreeCAD (export silently fails, importer scales text wrongly), CADCraft (BricsCAD refuses 14/23 saved files; AutoCAD AUDIT errors; version downgrade). Users judge a free CAD by whether the office's existing files open *exactly* and come back without AUDIT noise.
2. **Crashes and data loss.** FreeCAD 362 crash-titled issues in 22 months; LibreCAD 37 (fast-fixed); CADCraft 42 matches including GPU startup failures and an xref crash; concurrent-save data loss. Auto-backup is repeatedly what saves the user (LibreCAD 2014 review; FreeCAD recovery; CADCraft autosave).
3. **Performance on real files.** 5-20 MB DWGs are the threshold where users compare against AutoCAD ("AutoCAD handles files four times larger smoothly"); xrefs multiply the problem.
4. **Familiar input model.** Lost clicks while moving, right-click Enter, AutoCAD-style selection, aliases - nanoCAD wins its ease score by copying AutoCAD; LibreCAD explicitly refuses to.
5. **Documentation, help and support.** LibreCAD support 3.1/5; FreeCAD "near no customer service"; QCAD support 7.7/10; CADCraft's Discord-relay loses the reporter.
6. **Civil capability is absent everywhere** except a fragile FreeCAD add-on; the realistic open-source stack today is QGIS + Blender-GIS + a 2D CAD + spreadsheets, stitched by hand.
7. **UI complexity vs discoverability.** FreeCAD panels "confusing"; CADCraft tools existed but were not in the sidebar; LibreCAD "Object info" could not be found.

## 10. Wishes: what reviewers say an open-source CAD needs before they could switch

- Open the office's real DWGs (2004-2018, xrefs, layouts, dynamic blocks, assoc constraints) exactly, and save files that AutoCAD/BricsCAD open **with zero AUDIT errors** and no version downgrade (#604, #1041, #907, LibreCAD #3064).
- Keep unmodelled entities and xdata through round trips instead of dropping them; warn before any lossy save (README caveat; #540).
- Stay smooth on 20-50 MB drawings and multi-xref plans: background loading, culling, <12 s to first paint, <2.5 GB (#1076, #1625, #738).
- No crashes, and when something fails, recover: durable atomic saves, .bak, recovery journal, single-instance-per-drawing locks, conflict detection on save, AUDIT/RECOVER equivalents (#540, #752, LibreCAD 2.2.1.6 crash list).
- Robust GPU/platform startup (software fallback renderer when wgpu/Metal/OpenGL fails) (#1724, #1631, #955, README AMD note).
- AutoCAD-compatible muscle memory: command aliases, right-click Enter, click-while-moving, selection modes, DIMSTYLE/PLOT dialogs, dockable panels and saved workspaces (#1001, #729, #850, #429, nanoCAD ease-of-use score, LibreCAD #3162).
- Proper external references with clipping, in-place edit, relative paths, re-path without crashing, and an xref panel that also lists raster images (#1581, #813, #1636, #1756).
- Reliable printing/plotting in any unit and paper size (#1828, #1791, LibreCAD printing reviews).
- Integrated, current help and a responsive support channel where the reporter actually sees the answer (LibreCAD docs reviews; CADCraft Discord relay).
- For site work: TIN surfaces, contours, alignments/profiles, point import (CSV/LandXML), coordinate systems and GIS layers inside the CAD rather than via a lagging add-on (FreeCAD Trails status).
- A public, real-file test corpus and per-release round-trip reports (#1041 offer, LibreCAD PR #2855 approach).
- Linux/macOS parity without unsigned-DMG workarounds or compile-it-yourself installs (LibreCAD 2.2.1.3 note; BRL-CAD reviews).
- A sustainable model users accept: QCAD's one-time ~$50 Pro with a year of updates is cited approvingly; subscriptions are not.

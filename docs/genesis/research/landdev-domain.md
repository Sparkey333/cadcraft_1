Observed pattern: every stage uses two to four tools and hands data across by DXF, LandXML, CSV, shapefile or PDF. The expensive failure modes are at the hand-offs (CRS mismatch, lost attributes, stale references), which is exactly what Genesis says it wants to fix.

## 2. Requirements for a simplified but complete land-development CAD (priority and why)

Priority scale: **must** = cannot deliver a permit set without it; **should** = needed for a competitive v1.x; **later** = v2+.

### Geodesy and precision
- **must** Drawing-level coordinate reference system (EPSG code), grid-to-ground scale factor, NAVD88/NGVD29 vertical datum tag, on-the-fly reprojection of imported data. Every survey and every open-data feed below is in a different CRS; CAD that lacks this is where the 1-foot-off-the-map errors come from. Data: EPSG dataset via PROJ's proj.db (V: PROJ NEWS.md says proj.db imports the IOGP EPSG dataset) under EPSG terms (U: https://epsg.org/terms-of-use.html; the search-result summary says: free, acknowledge IOGP/EPSG ownership, no modified data may be attributed to EPSG, commercial packages allowed when value is added).
- **must** Bearing/azimuth/DMS input and display (N45°30'15"E, quadrant and azimuth), survey feet vs international feet, basis-of-bearings rotation.

### Points and COGO
- **must** COGO point object (number, N, E, Z, raw and full description), point groups, description keys to layers/symbols, CSV/PNEZD/LandXML import and export.
- **must** COGO commands: bearing-distance, inverse, intersection (bearing-bearing, distance-distance), traverse entry with closure and compass-rule (Bowditch) adjustment, mapcheck report with error of closure and area. Civil 3D's Map Check Report dialog (V: https://help.autodesk.com/view/CIV3D/2026/ENU/?guid=GUID-3D99202F-BDD3-4585-89E1-02DE47ECFD3A) is the reference behaviour: directions, distances, curve data, perimeter, area, closure, POB choice, clockwise/counter-clockwise.
- **should** Least-squares network adjustment (STAR*NET class) - later-stage survey firms need it; owner-builders do not.

### Parcels and legal descriptions
- **must** Parcel (closed lot) object with area, segment line/curve tables, lot numbering, right-of-way parcels, and a generated metes-and-bounds legal description with editable phrasing (Civil 3D keeps phrasing in an XML file, V: https://www.autodesk.com/support/technical/article/caas/sfdcarticles/sfdcarticles/Where-to-change-legal-description-report-phrasings-in-Civil-3D.html).
- **should** Reverse parser: paste a deed description and draw it (calls, curves, POB).

### Surfaces
- **must** TIN surface from points, breaklines, contours, GeoTIFF DEM and LandXML; boundaries and holes; contour generation with interval, index contours, smoothing and labels; spot-elevation labels; slope/aspect/elevation banding; profile and section sampling.
- **must** Volume between two surfaces (TIN difference, grid/average-end-area for checking), with cut, fill and net reported per region. Different methods must be labelled because results differ (Autodesk support note above).
- **should** LAS/LAZ point-cloud import with ground-class thinning (3DEP point clouds are LAZ 1.4, V search summary).

### Grading
- **must** Feature lines with elevations, grades and slope-to-surface (daylight) projections, pad grading, parking lot grading with high/low points, retaining wall top/bottom lines, and a live cut/fill balance.
- **must** ADA checks on routes: running slope <= 5% (1:20) for walks, cross slope <= 2%, ramps <= 1:12 with landings (2010 ADA Standards Ch. 4, U).
- **should** Mass-haul and topsoil strip, shrink/swell factors; **later** corridor/assembly modelling.

### Drainage and stormwater
- **must** Drainage areas with Tc, Rational and SCS curve-number runoff (CN from SSURGO hydrologic soil group, see data section), pipe sizing by Manning, HGL/EGL on profiles, inlet spread, stage-storage-discharge for ponds with simple routing.
- **must** NOAA Atlas 14 point precipitation-frequency fetch into the drawing (see data section) with the table stored in the project, not re-fetched.
- **should** LID/BMP objects (bioretention, permeable pavement, swale) sized to WQv; SWPPP disturbed-area and phasing tally; erosion-control symbol library.
- **later** Dynamic routing (embed or drive EPA SWMM; SWMM is open source per EPA, V search summary).

### Pipe and pressure networks
- **must** Gravity networks (structures, pipes, inverts, slopes, cover, rim), plan/profile labels, crossing and clearance report. **should** path-based pressure networks (valves, hydrants, fittings). **later** hydraulic analysis of water networks.

### Alignments and profiles
- **must** Horizontal alignments (tangents, circular curves), stationing, profiles with vertical curves, cross sections at stations; **should** spirals and superelevation; **later** corridors.

### Site rules (Genesis differentiator)
- **must** Parametric zoning rule set per project (setbacks by yard, max impervious %, lot coverage, height, parking ratio per use, accessible-space count from total, buffer widths) with a live compliance report that updates as the plan changes. Nobody does this well in CAD today; it is done in spreadsheets.
- **should** Well/septic/stream/wetland setback buffers as rule objects.

### Sheets and plan sets
- **must** Layouts/viewports, sheet index generation, title-block fields (project, sheet number of total, revision), revision clouds with deltas, north arrow and scale bar objects, batch PDF with bookmarks, match lines.
- **should** Plat template (certificates, monument legend, line/curve tables) and recording-size sheets.

### Files, exchange and references
- **must** DXF/DWG in and out; LandXML 1.2 (surfaces, alignments, profiles, parcels, CgPoints, pipe networks); GeoJSON, GeoPackage, shapefile; GeoTIFF DEM; CSV points; PDF out.
- **must** Project container that bundles the drawing with its references and data snapshots using relative paths, a link-health check, and provenance (source URL, fetch date, licence) for every imported data layer.
- **should** Live connectors to the open data sources in section 5 (NFHL, NWI, SSURGO, 3DEP, Atlas 14, parcels, OSM) with caching.

### Stability
- **must** Never-crash policy with panic guards, autosave/journaling and recovery; hostile-input tests for every parser (DXF, LandXML, LAS, GeoJSON, CSV).

### Old-school and neo modules
- **should** Solar siting/shadow study and PV layout with PVWatts link; rainwater catchment and cistern sizing; septic/leach-field sizing; wildfire defensible-space rings; floodplain BFE/freeboard check.
- **later** Geothermal bore fields, agrivoltaics, microgrid single-lines, constructed wetlands, 3D visualisation.

## 3. Old-school techniques and what the CAD needs

1. **COGO by bearing and distance.** Needs: bearing/azimuth parser and formatter; point-and-line creation by bearing-distance; inverse; traverse with closure and compass-rule adjustment; mapcheck report (model: Civil 3D Map Check Report, V URL above).
2. **Metes-and-bounds legal descriptions.** Needs: parcel -> description generator (POB, calls, curve data: radius, arc, chord bearing and distance, delta), phrasing templates, and a deed parser to draw from text. Reference behaviour: Civil 3D General Legal Description report (V). Survey standard: ALTA/NSPS 2021 Minimum Standard Detail Requirements (U: https://www.nsps.us.com/page/ALTA).
3. **Plats.** Needs: plat sheet templates at recording sizes, lot/block numbering, line and curve tables, monument symbols (found/set), easement hatches, dedication/certificate text blocks, vicinity map viewport. County recording rules vary (U).
4. **Contour interpolation from spot elevations.** Needs: TIN with linear interpolation along edges, contour tracing at any interval, index contours, a "interpolate between two spot grades" command for hand-style checks, and contour smoothing that never crosses.
5. **Hand-drafting conventions and lettering.** Needs: stroke drafting font (CADCraft already has its own in crates/fonts), lineweight-by-layer matching pen weights, standard line types (property, easement, centerline, fence, contour index/intermediate), north arrows, graphic scale bars, match lines, material hatch library. Convention source: ASME Y14.2 line conventions and lettering (U: https://www.asme.org/codes-standards/find-codes-standards/y14-2-line-conventions-lettering).
6. **Cisterns and rain catchment.** Needs: catchment object (roof polygon, pitch, material efficiency), gutter/downspout routing, cistern object (volume, overflow, first-flush), calc gallons = area_ft2 x rain_in x 0.623 x efficiency (constant verified in multiple public calculators, e.g. V: https://github.com/PDFCraftTool/OmniTools lib/calculations/solar/rainwater-collection.ts), monthly mass balance against demand. Manual: Texas Water Development Board Rainwater Harvesting Manual (U: https://www.twdb.texas.gov/publications/brochures/conservation/doc/RainwaterHarvestingManual_3rdedition.pdf).
7. **Root cellars.** Needs: below-grade structure object with earth-cover depth, frost-depth check (local), passive vent stacks, drainage to daylight, section generator. (U; vernacular references only.)
8. **Passive solar siting and orientation.** Needs: sun-path diagram for lat/lon and date, solar altitude/azimuth (implement Reda and Andreas, NREL/TP-560-34302, from the paper; pvlib's spa.py transcribes the report rather than NREL's C code, which carries its own licence, V: https://github.com/MatthewK84/ICS cpp/mount/src/spa_terms.hpp comments and https://github.com/CalebBell/fluids fluids/optional/spa.py), building long-axis orientation check (within ~15-30° of south, U), overhang depth from winter/summer sun angles, shadow casting from terrain, trees and neighbours. DOE guide (U: https://www.energy.gov/energysaver/passive-solar-home-design).
9. **Swales, terraces, keyline.** Needs: trace-contour-at-elevation command, on-contour or near-contour (keyline ~1:400 fall, U: Yeomans) polylines draped on surface, terrace spacing from slope, swale cross-section cut/fill, overflow spillway points. NRCS conservation practice standards (CPS 600 Terrace, 412 Grassed Waterway, 362 Diversion; numbering pattern verified for CPS 380, V: https://github.com/HiCSC/ClimateSmartPracticeStandards).
10. **Dry-stone walls.** Needs: wall object with batter (about 1:6), base width (about half to two-thirds of height), height limit, through-stone courses, tonnage estimate. (U: Dry Stone Walling Association https://www.dswa.org.uk/.)
11. **Earth building: adobe, rammed earth, cob.** Needs: thick-wall object (cob 12-24 in), stem-wall height above grade and roof overhang rule, one-storey prescriptive limit per 2021 IRC Appendix AU Cob Construction (Monolithic Adobe) (V: state code datasets https://github.com/thexqin/us-building-codes-dataset and California CRC arrangement text https://github.com/accelerate-x/building_codes), New Mexico earthen building code 14.7.4 NMAC (U), ASTM E2392 (U).
12. **Timber framing.** Needs: bent/bay grid, post/beam/brace library, footing/pier layout on the site plan, crane/laydown areas. (U: Timber Framers Guild https://www.tfguild.org/.)
13. **Straw bale.** Needs: modular thick wall (18-24 in) with bale course counts, toe-up height, roof overhang, one-storey prescriptive per IRC Appendix AS Strawbale Construction (V, same code datasets); light straw-clay per Appendix AR (V, same source).
14. **Thatch and vernacular green roofs.** Needs: roof object with pitch (thatch needs steep pitch, ~45°+, U), area, runoff coefficient change feeding the drainage calc, structural load note.
15. **Windbreaks and shelterbelts.** Needs: linear planting object with species rows, spacing, mature height H, orientation vs prevailing wind, protected-area polygon (~10 H downwind, U rule of thumb), per NRCS CPS 380 Windbreak/Shelterbelt Establishment and Renovation (V: practice_code 380 in the NRCS practice-standard dataset above).
16. **Septic systems and leach fields.** Needs: tank + drainfield trench objects, area from percolation rate and bedroom count (state tables), setbacks (well, property line, water body, foundation), reserve area, plan and profile. (U: EPA Onsite Wastewater Treatment Systems Manual EPA/625/R-00/008.)
17. **Wells.** Needs: well point with setback rings, well-log attributes, link to USGS NWIS groundwater levels (V endpoint https://waterservices.usgs.gov/nwis in public code) and state well-log databases (U).
18. **Magnetic bearings in old deeds.** Needs: declination for date and place (NOAA NCEI geomagnetic calculator, U: https://www.ngdc.noaa.gov/geomag/calculators/magcalc.shtml) to rotate magnetic calls to true/grid.
19. **PLSS (township/range/section) descriptions.** Needs: aliquot-part generator and BLM CadNSDI PLSS grid import (U: https://gbp-blm-egis.hub.arcgis.com/).
20. **Hand earthwork methods (grid method, average end area).** Needs: these as alternative volume engines so results can be reconciled with old hand calcs and contractor estimates.

## 4. Neo techniques and what the CAD needs

1. **Solar PV array layout with shading.** Needs: module/string/row objects (tilt, azimuth, ground-coverage ratio), terrain and obstruction shadow casting by hour and month, inter-row shading, and a PVWatts v8 call. Endpoint and parameters verified from NREL's developer-docs source: `GET /api/pvwatts/v8.json?api_key=...&lat=&lon=&system_capacity=&module_type=&losses=&array_type=&tilt=&azimuth=&gcr=&dc_ac_ratio=&inv_eff=&albedo=&bifaciality=&soiling=...&dataset=nsrdb` (V: https://github.com/NatLabRockies/developer.nlr.gov source/docs/solar/pvwatts/v8.html.md.erb). The developer host moved from developer.nrel.gov to developer.nlr.gov in 2026 (search-result summary says the old domain was retired 2026-05-29; many public clients still hard-code the old host). Free API key; rate limits unverified.
2. **Rainwater harvesting sizing from Atlas 14 and roof areas.** Needs: Atlas 14 point fetch `https://hdsc.nws.noaa.gov/cgi-bin/hdsc/new/cgi_readH5.py?lat=..&lon=..&type=pf&data=depth&units=english&series=pds` (V in several public clients, e.g. https://github.com/rogerlew/wepppy and https://github.com/ARS-SWRC/agwa which also cite NOAA's FAQ on automated requests at https://www.weather.gov/owp/hdsc_faqs), monthly normals (NOAA NCEI 1991-2020, U), demand profile, daily mass balance, tank size and overflow; report.
3. **Greywater.** Needs: source fixtures, branched-drain or mulch-basin objects, surge tank, flow estimates per plumbing code appendix (U), setbacks from property lines and wells.
4. **Bioswales, bioretention, permeable paving.** Needs: LID objects (surface area, ponding depth, media depth, underdrain, infiltration rate from soils), WQv sizing, drawdown time; optionally drive EPA SWMM's LID module (SWMM open source, repo V) or the EPA National Stormwater Calculator (repo V).
5. **Green roofs.** Needs: roof object with media depth and retention, modified runoff coefficient, structural load note (U: FLL green roof guideline; Green Roofs for Healthy Cities).
6. **Geothermal ground loops.** Needs: bore-field grid or horizontal-trench object with spacing and depth, total loop length from load (IGSHPA design guidance, U), conflict check against utilities, septic and trees.
7. **EV charging, microgrids, battery storage.** Needs: EVSE stall objects incl. accessible EV spaces, conduit runs, transformer/switchgear pads, battery enclosure with clearances (NFPA 855, U), EV-ready/EV-capable percentage rule per adopted code (e.g. CALGreen, U), simple single-line export.
8. **Agrivoltaics.** Needs: elevated PV rows with crop strips, row spacing for equipment, shading map for crop light (U: NREL InSPIRE https://openei.org/wiki/InSPIRE).
9. **ADUs, prefab, 3D-printed earth homes.** Needs: ADU rule set (size caps, 4-ft side/rear setbacks in California, U: HCD ADU handbook), prefab module library with transport path check, 3D-printed earth footprint/print-envelope object (WASP TECLA 2021, ICON, U).
10. **Net-zero and Passive House siting.** Needs: solar-access envelope, orientation and glazing-by-orientation report, shading, export of site data (lat/lon, climate zone, elevation) to PHPP/WUFI (U: PHIUS).
11. **Wildfire defensible space.** Needs: Zone 0 (0-5 ft ember-resistant), Zone 1 (5-30 ft), Zone 2 (30-100 ft) rings from building footprints (CAL FIRE, U: https://www.readyforwildfire.org/prepare-for-wildfire/defensible-space/), vegetation-spacing rules on slopes, FHSZ layer fetch (V endpoint: https://egis.fire.ca.gov/arcgis/rest/services/FRAP/FHSZ/MapServer and FHSZ_SRA_LRA_Combined, fields HAZ_CLASS/HAZ_CODE).
12. **Floodplain resilience.** Needs: NFHL zone and BFE attach, freeboard rule (ASCE 24, U), finished-floor vs BFE check, fill and compensatory-storage volumes, floodway no-rise flag, elevation-certificate data export.
13. **Heat-island mitigation.** Needs: tree-canopy polygons at mature crown, shaded-parking percentage at a chosen date/time, cool-pavement/roof SRI attributes, canopy-coverage report (U: EPA heat-island resources).
14. **Smart irrigation.** Needs: hydrozone polygons with plant factor and irrigation efficiency, ET-based water budget (MAWA/ETWU style per California MWELO, U), controller object with weather-based rating (EPA WaterSense WBIC spec, U).
15. **Composting toilets.** Needs: fixture object with no drainfield, NSF/ANSI 41 attribute (U), setbacks for leachate handling; reduces septic sizing input.
16. **Constructed wetlands.** Needs: cell objects sized by hydraulic/organic loading, berms and liner, hydraulic retention time (U: EPA 2000 manual Constructed Wetlands Treatment of Municipal Wastewaters).
17. **Hempcrete.** Needs: non-structural infill wall assembly (~12 in) under 2024 IRC Appendix BL Hemp-Lime (Hempcrete) Construction, limited to non-structural infill, two storeys, low seismic, and adopted only where a jurisdiction adopts it (V: https://github.com/JinnZ2/BioGrid2.0 docs/science/REFERENCES.md citing https://codes.iccsafe.org/content/IRC2024P2/appendix-bl-hemp-lime-hempcrete-construction; also present in the Georgia IRC-2024 dataset).
18. **Mass timber.** Needs (site side): structural grid, fire-separation distances for Type IV-A/B/C (IBC 2021, U), crane and laydown areas, delivery path. Mostly a building-CAD topic.
19. **LiDAR and drone photogrammetry topo.** Needs: LAS/LAZ import, ground classification filter, DEM from 3DEP 1 m tiles (cloud-optimized GeoTIFF, search-result summary), surface comparison to field survey.
20. **Smart data provenance.** Needs: every fetched layer stores source URL, fetch date, licence and attribution string and prints them on the sheet (ODbL and CC-BY both require it).

## 6. Key claims to carry into the comparison

1. Civil 3D ships Hydraflow Storm Sewers, Hydrographs (SCS and Rational, pond routing) and Express (culverts, channels, inlets, weirs) and Storm and Sanitary Analysis as installed extensions. V.
2. Civil 3D's grading auto-balance iterates to a target net volume with 0.1% tolerance and may need re-running. V.
3. Civil 3D survey import accepts field book, LandXML, point files and drawing points; linework requires description keys, linework code sets and figure prefix databases set up in advance. V.
4. Civil 3D pipe-network interference check supports 3D proximity by distance or scale factor; path-based pressure networks arrived in 2021. V.
5. Civil 3D's legal-description phrasing is an editable XML file, and its mapcheck supports POB choice, direction of travel and chord-vs-arc traverse. V.
6. NOAA Atlas 14 point data are retrievable from a CGI endpoint widely used in public code; Atlas 15 is a 2024 Montana pilot with CONUS estimates in peer review in 2026. V (secondary).
7. USGS 3DEP products are public domain and the TNM Access API returns tile lists for the 1 m DEM and LPC datasets. V.
8. The NSRDB is CC BY 3.0 US on AWS and NREL's developer host is now developer.nlr.gov. V / search summary.
9. PVWatts v8 accepts albedo and bifaciality inputs. V.
10. FEMA NFHL layer 28 carries FLD_ZONE, SFHA_TF and ZONE_SUBTY. V.
11. SSURGO's map-unit hydrologic soil group is muaggatt.hydgrpdcd via Soil Data Access T-SQL. V.
12. 2021 IRC has Appendix AS (straw bale), AR (light straw-clay) and AU (cob); 2024 IRC adds Appendix BL (hempcrete) as non-structural infill, adopted jurisdiction by jurisdiction. V.
13. NRCS practice standard 380 is Windbreak/Shelterbelt Establishment and Renovation. V.
14. Overture Maps is CDLA-Permissive-2.0 except OSM-derived content (ODbL). V.
15. ADA 2010 Standards Table 208.2 scopes accessible spaces by lot size; one in six accessible spaces must be van-accessible. V (DOJ source repo).
